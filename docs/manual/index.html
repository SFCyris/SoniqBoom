Self-hosted · Browser-based · Zero cloud

Your whole collection,
from SID to FLAC.

SoniqBoom is a self-hosted music server that plays the formats other servers forget — chiptune, tracker modules, SID, MIDI, console rips — alongside FLAC, DSD and the common lossy codecs, streamed to any browser on your network.

01What's inside

One server for the everyday lossless library and the weird corners of music history.

🎮

Chiptune & console

SID, NSF, SPC, GBS, VGM, AY, KSS, SAP, GYM, HES — rendered on the fly, with tunable 6581 / 8580 SID fidelity.

🎹

Tracker modules

MOD, XM, IT, S3M, MED and the full libopenmpt family — each channel metered on its own, up to 32 at once.

💾

Amiga & Atari exotica

About 175 UADE players — TFMX, Future Composer, Jochen Hippel, SidMon — plus AHX, HivelyTracker and Atari ST SNDH / YM / SC68.

🕹️

Portable & console rips

The PSF family in full — PSF, PSF2, GSF, USF, 2SF, SSF, DSF and NCSF — straight from the reference emulation cores.

🟥

AdLib / OPL FM

The sound of DOS gaming — id Software IMF, ROL, CMF and more, played by AdPlug with the Nuked OPL3 emulator.

🎵

Lossless & DSD

FLAC, ALAC, WAV, AIFF, WavPack — plus 1-bit DSD (DSF / DFF / WSD) and the common lossy codecs: MP3, AAC, Ogg Vorbis, Opus and Musepack.

🌌

Visual library

Per-channel VU meters, a live spectrum fallback, an animated decode signal-chain, and the Library Galaxy star-field.

🏷️

Scene origins

Retro modules matched by fingerprint against Modland fill in the original scene author and the tune's provenance path.

🗄️

Network libraries

Attach FTP, SMB and WebDAV shares and web folders straight from the admin panel — no operating-system mount required.

🌐

Modland catalogue

One switch lists Modland's module archive — hundreds of thousands of tunes — in your library; a tune is downloaded only when it is needed — to play it or to read its details.

📱

OpenSubsonic API

Connect Amperfy, Symfonium, DSub, Feishin and the wider Subsonic app ecosystem to your server.

📻

Internet radio

A curated demoscene & chiptune station pack plus the worldwide directory — HLS and classic streams alike, with live now-playing titles and cover art.

📡

Casting Beta

Send playback to Chromecast, AirPlay and DLNA receivers — even rendered SID and tracker tunes.

👥

Multi-user & PWA

Accounts with roles, multi-room sync, instant mixes, smart playlists, offline downloads, time-synced lyrics, scrobbling, and an installable web app.

02Install & first run

SoniqBoom runs on macOS and Linux. Point it at your music, hit scan, and open it in any browser.

Before you start. You'll need macOS or Linux and git (macOS: xcode-select --install, which adds the Xcode Command Line Tools; Linux: apt install git or your distro's equivalent). On Linux you also need curl and a distribution whose Python 3 is 3.11 or newer — the installer stops if git or curl is missing; on macOS it installs Homebrew and Python 3.12 for you. The installer fetches everything else — ffmpeg and all the renderers. Any modern desktop or mobile browser can play the library; plan for memory that grows with your collection, since the whole index lives in RAM (see System notes).

macOS & Linux — one-shot install

# clone, install everything, and start the server
git clone https://github.com/SFCyris/SoniqBoom.git
cd SoniqBoom
bash install.sh        # Python, ffmpeg, and ALL retro renderers
bash run.sh            # starts the server on port 8080
The installer sets up every renderer for you. One run of install.sh installs sidplayfp (SID), fluidsynth (MIDI), libopenmpt (trackers), uade (AHX + Amiga exotica), libgme (console chiptunes), adplay (AdLib/OPL), the Atari ST renderers (psgplay and sc68), zxtune123 (the PSF console-rip family, MED 2–4 modules and VGM files that use a chip libgme lacks) and kssrender (MSX KSS music, built from the libkss sources on every system; it needs a C compiler and git) — Homebrew packages and source builds on macOS; on Linux your distribution's packages (apt, dnf, pacman or zypper), the prebuilt zxtune123 and source builds of psgplay, uade and sc68 where the distribution has none, plus lha from lhasa for LHA archives where the distribution packages it. On Linux, sidplayfp is built from source with libsidplayfp 3.1 and libresidfp into /usr/local (a few minutes), unless one with libsidplayfp 3.1 or newer is already installed; if the build fails, the distribution's package is used. On Debian / Ubuntu, if AdLib files don't play, install the adplay package. The HivelyTracker decoder and the StSound engine (Atari ST .ym) are bundled with SoniqBoom and compiled the first time such a file plays, so the server needs a C and a C++ compiler — the installer adds them. MIDI needs a SoundFont: under gear → Renderers → Soundfonts, use ↑ Upload .sf2/.sf3 or pick one from Download Known Soundfonts. Every other format in this guide plays out of the box.

run.sh starts the server in the background and writes its log to log/soniqboom.log in SoniqBoom's data folder. bash shutdown.sh stops it and bash restart.sh restarts it; to use another port, start it with bash run.sh --port 9090 and give shutdown.sh and restart.sh the same --port. On macOS, run.sh also puts a 🔊 icon in the menu bar with Open SoniqBoom, Start SoniqBoom, Restart SoniqBoom, Stop SoniqBoom, Settings, Status, Source on GitHub and About SoniqBoom; Quit Menu Icon (server keeps running) removes the icon and leaves the server running. The server listens on every network interface; to reach it from this machine only, set "host" under "server" in SoniqBoom.conf to "127.0.0.1" and restart it.

Or run it in Docker

One container ships ffmpeg, all the renderers and a General MIDI SoundFont. Your music mounts read-only at /music; everything SoniqBoom keeps — the library index, user accounts, the settings file (network shares, folder aliases, services and the other admin settings), prefs.json, the cover-art and render caches, SoundFonts you add, saved share passwords and last.fm / ListenBrainz logins, and logs — lives in one named volume (/data), so it is kept when the container is recreated, for example by an update.

Before the first start, put your music in a music folder inside the SoniqBoom folder (or make music a symlink to your music folder — links inside it that point elsewhere don't work in the container) — or change the ./music line in docker-compose.yml to your music's path. The first docker compose up -d builds the image.

# clone, build, and start — then create the first admin
git clone https://github.com/SFCyris/SoniqBoom.git
cd SoniqBoom
docker compose up -d
docker compose exec soniqboom soniqboom-setadm -user alice -passwd 'a-strong-password'

Open http://<host>:8080, sign in, and add /music as a library folder. For automatic HTTPS on your own domain, the repo includes a Caddy stack: point your domain's DNS at this host, open ports 80 and 443, replace music.example.com in deploy/Caddyfile with your domain, stop the plain setup (docker compose down; the volume is kept), then run docker compose -p soniqboom -f deploy/docker-compose.https.yml up -d from the SoniqBoom folder. -p must be the plain setup's project name: the part before _soniqboom-data in docker volume ls (soniqboom for a git clone, soniqboom-main for a folder unzipped from the ZIP). Use the same -p and -f with every docker compose command for this setup. An HTTPS setup first started without -p uses its own volume, deploy_soniqboom-data: keep leaving -p out for that one.

To update, run only the block for your setup. Everything on /data is kept, including the library index, so there is no full rescan. A container from an image before 1.14.0 kept its settings, and the SoundFonts added in it, inside the container, so after the first update to 1.14.0 or later, settings (shares, services, sign-up and password rules, renderer settings, the Re-apply automatically switches) need to be set once more; from then on they're kept. To keep those SoundFonts, copy them out before you update (docker cp soniqboom:/app/soundfonts ./old-soundfonts) and add them again under gear → Renderers → Soundfonts (↑ Upload .sf2/.sf3). The new container can't read that container's last.fm / ListenBrainz logins either: enter them again under gear → System → My Account (admin accounts only).

# Compose, built from source
git pull
docker compose up -d --build

# Compose, prebuilt image (image: line enabled)
docker compose pull
docker compose up -d

# HTTPS setup, built from source
git pull
docker compose -p soniqboom -f deploy/docker-compose.https.yml up -d --build

# HTTPS setup, prebuilt image (image: line enabled and build: .. commented out in
# deploy/docker-compose.https.yml — as shipped, that file builds from source)
docker compose -p soniqboom -f deploy/docker-compose.https.yml pull
docker compose -p soniqboom -f deploy/docker-compose.https.yml up -d

Full details live in DEPLOY.md; what a backup needs to include is under Back up & restore.

Then, the first time you start it

Used Docker above? You already created your admin — skip to step 2 (Sign in). Steps below are for the native macOS/Linux install.
  1. Create the first admin account. A fresh install has no users; the native install prompts you for a username and password on the terminal. If it didn't prompt — or to add/reset one later — run this from inside the SoniqBoom folder (a new account made this way is an admin unless you add -role edit or -role readonly; for an existing account it changes only what you pass): 
    bash setup-admin.sh -user alice -passwd 'changeme123'
  2. Sign in. Open http://localhost:8080 and enter those credentials. Your name then shows in the header, with ⎋ to sign out.
  3. Open the admin panel with the gear icon (top-right).
  4. Add a music folder — on the Library tab under Music Folders, choose Local Path and + Add for a folder on this machine, or Network Share and + Connect for an FTP / SMB / WebDAV share.
  5. Wait for the scan — roughly two minutes per 50,000 tracks; the header shows its progress (Scanning …% — click it to open the admin panel). Your library is ready when it finishes.

03Browse your library

All Tracks, Artists, Album Artists, Albums, Genres, Years, the Scene view and the Library Galaxy — plus folder trees that mirror your shares, and instant search.

Folders. Each music folder and share is a root of the sidebar's folder tree (🌐 marks a share). Click a folder to list its tracks; a folder that holds only subfolders lists every track below it. With a folder focused, → / ← open and close it, ↑ / ↓ move through the tree and Enter lists it.

Getting around a big library

Every track list in the main view — All Tracks, a genre, artist, album, folder, search or smart view — has Play all and Shuffle buttons in its header — browse to a genre, artist or album and start it playing in one click, or press P to play and Shift+P to shuffle. A big genre or artist lists its first 2,000 tracks — the header says so — while Shuffle covers every match; a search lists all of its matches (see Search). Track lists of more than 40 rows, unsorted or sorted by title, artist, album or album artist (search results: sorted by one of these), and long group lists, show an A–Z rail down the left edge — click a letter to jump straight to that part of the list (#, at its foot, jumps to titles that start with a digit or sign). In a list shown whole — a folder or a playlist — a column with nothing in any row (such as Album Artist for a folder of chip tunes) is left out; in a window 1100 px wide or less Album Artist and Duration are headed Alb. Artist and Time. Right-click a track (or a selection) for Play, Play next, Add to queue, Add to playlist…, a row of rating stars, the Problem report, Go to artist or Go to album to pivot to everything by that artist or on that album, Find folder to open the track's folder in the folder tree with the track marked (handy for a search result), and Get info for Track Info. And the ◎ Locate button on the player bar — or the G key — scrolls the list back to whatever's playing, which is marked with a small animated equalizer. If part of a long list can't be loaded from the server, its rows say so and offer Retry.

Select, sort and arrange

Click a row to select it and double-click it to play from there (J / K move the keyboard focus and Enter plays the focused row); ⌘/Ctrl-click and Shift-click select several, and with two or more selected a bar offers ▶ Play, + Queue, + Playlist and × Clear. Click an Album Artist or Album cell to open it; click an Artist cell to search for that artist (artist:"name": the tracks whose artist or album artist is that name). Artists, Album Artists, Albums, Genres and Years list each name with its number of tracks and a filter box above the list; tracks without the tag are under [No Artist], [No Album Artist] or [No Album]. The ⊞ button switches an Albums list to a cover grid and back. The browser's Back button goes up one level, and after a reload SoniqBoom reopens the sidebar view (Artists, Albums, the Galaxy, a smart view …) you had open.

The Compo column shows the party competition a tune entered and its place — Revision 2019 · Oldskool Music · 2nd of 9 — and appears by itself in a party's list and in a folder or other list loaded whole that holds such tunes; to see it in All Tracks and search results too, or to hide it, right-click the header row. Click a competition's name in it to list that competition's entries in placing order (← Back returns to the whole party). Track Info shows the same as Party. Click a column header to sort by it, and again to reverse; the sort is remembered in this browser. Sorting ignores case and leading or trailing spaces, puts tracks with an empty value last (first when reversed) and orders equal values the same way every time, so a list sorts the same whatever its size and wherever it was opened from. Year and Duration sort by the number, with tracks that have none last; Track sorts by disc and then track number, with tracks that have no track number last; Location sorts by the file's path. Right-click the header row to choose the columns (#, Cover, Title, Album Artist, Artist, Album, Track, Year, Duration, Type, Location and ★ — Location starts hidden), and drag a header's edge to change its width. A list of more than 5,000 tracks, such as All Tracks in a big library, sorts by Title, Album Artist, Artist, Album, Year, Duration or Type; a folder of more than 2,000 tracks, or one listing every track below it, keeps its folder order.

Several artists or genres in one tag

When a tag holds several values — several artists, album artists, composers or genres in an MP3, AIFF, FLAC, Ogg, Opus, M4A, DSD or other tagged file — SoniqBoom keeps them all. The artists are shown together, as “Artist A • Artist B”, and each of them has its own entry in the Artists and Album Artists views with the track listed under each; every genre is listed in the Genres view. Subsonic apps get each artist and genre on its own too. If a FLAC, Ogg, Opus or M4A file shows only one of its values, it shows the others once the file changes and is read again.

The Library Galaxy

Every track in your collection rendered as a drifting star-field — each format its own glowing constellation, sized by how much of it you own. The legend doubles as a census of your library. Click a format's chip under the star-field (or its row in List) to list that format's tracks (Format: …; Back returns to the Galaxy). The toolbar switches between Galaxy and List — a table of Format · Tracks · Share you can sort and narrow with Filter formats… — and the family chips Trackers, Chiptune, Lossless, Lossy and Other narrow both. While visualizations are switched off, or your system asks for reduced motion, the view shows the list.

Scene: composers, games, platforms, parties and groups

When the library has composer tags, games, retro platforms, demoparties or demoscene groups, the sidebar's Library list gains Scene. It lists one kind of entry at a time, and the keys above the list switch between them:

  • Composers — each composer, with the number of tracks. A tune credited to two composers (Rob Hubbard • Ben Daglish) counts under each of them.
  • Games — each game a tune is the music of, from the file's own tags, Modland, Demozoo, the UADE song database or the game lists.
  • Platforms — the computer, console or sound chip a retro tune is for: SID (the C64's chip), Amiga, Atari ST, NES, SNES, PlayStation, AdLib, MIDI and more — the same names as its platform genre.
  • Parties — the demoparty a tune was released at (from Demozoo). A party's tracks are grouped by the competition they entered (Oldskool Music, Tracked Music …), each in placing order — 1st, 2nd, 3rd — with the tracks of no known competition last.
  • Groups — the demoscene groups of the composers (from Demozoo).

A key shows only when its list has entries. Click an entry for its tracks, with Play all and Shuffle; ← Back returns to the list. The filter box above a list narrows it, and the Scene view opens on the list you used last in this browser. Parties and Groups fill in once the Demozoo index has been applied (gear → Metadata → Scene groups (Demozoo)); when that card says to refresh the index for party competitions, Download / refresh index and then Apply to library add them. On the phone page, the Library's Composers, Games, Platforms and Parties keys list the same.

04Find anything

A search bar that understands field operators, and smart views that surface your library by listening habit.

Search with field operators

Type anything to search titles, artists, album artists, albums, composers, scene groups and games at once: every word you type must match, and a word of two or more characters matches the start of a word (var finds “Varga”), and case and accents don't matter (oorni finds “Öörni”). As you type, a preview lists the first matching tracks and how many tracks match (and, while a Stations list is open, matching radio stations first — see Internet radio): ↓ / ↑ pick one and Enter plays it; otherwise Enter opens the full results. They list every match — the header gives the exact number, e.g. Search: crack — 18,432 matches — and, like All Tracks, load as you scroll. A new search lists its best matches first (Best match): a title that is exactly what you typed, then tracks with all of your words as whole words in one field, then tracks where your words appear together, in order, then tracks with all of your words in one field. A whole word counts more than the start of a word, so searching ghost lists the artist Ghost before the title “Ghostbusters”. Among equal matches, a match in the title counts more than one in the artist or album artist, which counts more than one in the album, which counts more than one in the composer, scene group or game. Equal matches list newest first. A search made only of field operators (format:SID year:>2020) lists newest first; with words besides the operators, the operators narrow the matches and the words rank them. The preview shows the first of the same matches. Click a column header (Title, Artist, Album Artist, Album, Year, Duration or Type) to sort all of the matches by it, and click it again to reverse the order; the Best match button in the results header puts the best matches first again (for a search of only field operators it reads Newest first). Track and Location sort a search of up to 2,000 matches. On a phone the results list best matches first, and the number of matches says so — also with the Title, Artist, Album, Genre or Game key, where the best match is judged on that field. Play all and Shuffle play all of the matches, and Shift-click selects a range of rows as in All Tracks. When a scan finishes, or which tracks can play changes while Hide is on, the open results are read again where you are. Esc closes the preview and × clears the box. The first time you click into the empty box, the common operators (artist:, album:, game:, year:, format:, added:, length:, rating:) show as chips you can click. Narrow it with field operators — stack as many as you like, and put - in front of one to leave its matches out:

artist:Ghost  album:Impera  year:>2020  format:FLAC  -live

Every operator, with examples, is listed under Search options below.

Press / anywhere to jump to the search box. A mistyped operator (an unknown field:) is flagged in the preview as Unknown field instead of silently returning nothing.

Search options

An operator is a name, a colon and a value, with no space after the colon: year:1990. Operator names work in any case (Artist:). Quote a value that contains spaces: artist:"The Ghost Inside". Everything that isn't an operator is searched as words, as above, and every operator and word must match — the same operator twice too (folder:music folder:live). Several values separated by commas match any of them: format:flac,alac (a space after the comma is fine; quote a value that contains a comma). A value an operator can't read — year:abc, track:remix, length:long, status:fine — is searched as words instead, and so is a word:value whose word is no operator. The same operators work in Play all, Shuffle, smart playlists (⚡ Save search) and in the search of Subsonic apps.

05Playlists

Hand-built collections that stick, and saved searches that keep themselves current.

Build a playlist by hand

Open the Playlists panel from the sidebar's Playlists section or the Playlists button in the player toolbar, then press + New to start one and name it. Add tracks three ways: select two or more rows in the library and click + Playlist in the bar that appears, or right-click a row and choose Add to playlist… — either drops them into an existing list or a brand-new one — or drag them straight into the panel. Inside a playlist a drag handle reorders tracks, and you can grab several at once to move them together. Delete a playlist whenever you're done with it.

Click a track in a playlist to play the playlist from there. ⌘/Ctrl-click and Shift-click select tracks, and Delete or Remove takes them out. An amber 2× marks a track that is in the playlist twice, and ⧉ the same song from another location. Each account's playlists are its own — other accounts don't see them unless you share them (below). Read-only accounts can make and change their own playlists too. To rename or delete an open playlist, use its ⋯ menu; on the phone page, long-press it and choose ✎ Rename.

The playlist view

An open playlist starts with a header: a mosaic of the first four different covers in it (one cover when there are fewer, the main format's symbol when there are none), who shares it — shared by its owner for one you imported, or how many listeners imported one of yours — its name, the number of tracks, the total length and the formats it holds (for example FLAC 6 · SID 3 · MOD 2), with a bar coloured by kind of format — lossless, lossy, SID, tracker, chip, MIDI — showing the mix. Play starts it from the top and turns into Pause while it plays; Shuffle plays it in random order; Share (your own playlists) or Unsubscribe (imported ones) work as described below; the ⋯ menu adds the whole playlist to the queue, saves it as a file (Export as M3U…, Export as XSPF…), renames it or deletes it.

Each row shows the cover, title and artist, the format (left out in a narrow window), the length and a small waveform of the track. A track shows its waveform once it has been played or readied to play next; until then — and for a single tune picked from a multi-tune file — an empty strip stands in. The row that is playing fills its waveform as the track goes on. To move tracks, drag them by the handle at the left of a row: a line shows where they will land, and the rows slide into their new places. Imported and smart playlists can't be reordered, and tracks can't be added to or removed from them.

In the Retro hi-fi style the playlist is a cassette insert: the name in a handwritten style, the total length on a tape counter, and a turning tape reel beside the track that is playing. Both styles follow the light and dark themes. With Visualizations switched off, or when your system asks for reduced motion, the reel and the waveform's shimmer stay still; the waveforms and the playing track's progress still show.

Share and import playlists

Open one of your playlists and press Share to make it available to every account on the server; a Shared badge marks it in the sidebar. To use someone else's shared playlist, press Import… in the Playlists panel and tick the playlists you want — they appear in your sidebar marked by and their owner's user name. An imported playlist follows the owner's changes and can't be edited by you: play it, queue it or Unsubscribe to remove it again (or untick it under Import…). When the owner stops sharing or deletes the playlist, it disappears for everyone who imported it. Read-only accounts can import shared playlists but not share their own. On the phone page, Import shared playlists… does the same. In Subsonic apps a shared playlist is a public one, and an imported one is listed with the playlists of your own.

Playlist files — M3U and XSPF

To bring a playlist from another player, press Import… in the Playlists panel and Choose a file… under A playlist file: an M3U, M3U8 or XSPF file. SoniqBoom makes a new playlist named after the file's own title, or after the file name. It finds each track in your library by its path, then by its file name and the folders around it, so a playlist from another computer, another drive or Windows still matches, and then by artist and title. A length in the file must agree within 5 seconds. When several tracks fit equally well and nothing tells them apart, the entry is left out rather than guessed. The dialog says how many tracks it found and lists the ones it didn't, with the reason.

To take a playlist elsewhere, open it and choose Export as M3U… or Export as XSPF… in the ⋯ menu; a smart playlist exports the tracks it lists now. Each entry is the file's path on the server, or a share file's address without its user name or password, so another player on the same computer can open it. A file exported here and imported again finds the same tracks, a single tune of a multi-tune file included (an online-collection tune that is also a file in your folders comes back as your file). A smart playlist exports up to the 500 tracks it lists. On the phone page, Import a playlist file… sits at the top of the playlists, and a long press on a playlist offers the exports.

Smart playlists — save a search

Any search can become a playlist that keeps itself up to date. Type a query — say format:SID year:>1988 — and press ⚡ Save search, which appears next to the search box while it holds text. Name it, and it appears under Playlists with a ⚡ marker. Opening it re-runs the saved search — up to 500 matching tracks — so new tracks that match are included automatically; a smart playlist can't be edited by hand. Every search option works in a saved search; plays: and played: read the plays of whoever opens the playlist. Smart playlists work in Subsonic apps too.

Keep an Instant Mix. Built an Instant Mix radio you love? Its Save as playlist button freezes the current mix into a playlist you can return to any time.

A hand-picked demoscene & chiptune station pack, plus the worldwide directory — HLS and classic streams alike, with live now-playing titles.

The player shows the station and the track that's on air (the phone page shows the station's name and logo), and the ★ button on the now-playing card adds it to your Favorites or removes it.

The Stations view. The big round button pauses and resumes; beside it are ★, ⏹ (stop) and ⓘ (station details). With nothing playing, the round button plays the station the dial's needle points at (after a stop, the first one).

Click a name — or anywhere on the scale for the nearest station — drag the needle and let go, or scroll sideways over the dial (once the dial has focus, the mouse wheel tunes too; otherwise it scrolls the page); ‹ / › beside it tune the neighbouring station. With the keyboard, Tab to the dial, then ← / → one station, Page Up / Page Down five, Home / End the first / last: the needle moves at once and the station tunes in when you stop; Enter tunes in straight away. A long list scrolls sideways along the dial. On a page with no stations of its own (World's continents and countries) the dial keeps the list the playing station came from. Live now-playing. In the web app, as each song changes, the current track's title appears in the player — split into artist and song when the station provides it — read from classic ICY stream metadata and the in-band metadata modern HLS streams carry. Station details. While a station plays, the ⓘ button in the player toolbar opens its details — tags, website, the live now-playing title, and every available stream with the one you're hearing marked.

07Now playing

Double-click any track and it plays — even a 1987 SID tune or a 64-channel tracker module, rendered to audio on the fly.

First plays start at once. A retro tune that isn't in the render cache yet starts playing within a fraction of a second while the rest of it renders — SID, MIDI, AdLib / OPL, Atari ST SNDH, the PSF family, console chiptunes and Amiga modules alike (a tune that opens with silence starts once its first sound is rendered). In Safari, a first play whose length isn't known yet — a MIDI file, for example, or an AdLib, Amiga or console tune that hasn't played before and states no length — starts once its render is complete. Subsonic apps and DLNA players (the DLNA Media Server is in Beta) start SID and SNDH tunes while they render; a Subsonic app that asks for MP3 or another format gets that quick start for every one of these formats, unless it asks for a start offset or — for any but SID and SNDH — an estimated file size. Casting (Beta) starts SID, MIDI, AHX and console-chiptune tunes the same way.

Per-channel VU meters for tracker modules

Open any module and SoniqBoom shows a meter for each of its channels — up to 32 — dancing in real time, alongside the module's real metadata: channel and pattern counts, instrument names, and the embedded text messages trackers are famous for. A live signal path sketches how the playing track reaches your speakers — naming the renderer for SID, the classic tracker formats, HivelyTracker, AHX, MIDI, NSF, SPC and DSD files, and a decode step for other formats; it shows while the Now-playing visualizations are on (in Retro hi-fi as a row of labelled steps, the active one lit).

C64 SID tunes of up to ten minutes get a three-voice meter, built in the background the first time a tune plays (the spectrum shows until it is ready), and Amiga player formats played by UADE, AHX included, get per-voice meters from an extra background pass (Playback preparation) for tunes of up to seven minutes. For formats without per-voice data — HivelyTracker, console chiptunes, AdLib / OPL, Atari ST and the PSF family — the meter falls back to a live 32-bin FFT spectrum analyser, labelled as such; MIDI files and ordinary audio files show no meter. Prefer a different look? Set VU meter style to Circuit board under gear → System → Settings → Visualizations (gear → Preferences for accounts without admin rights) — a skin driven by the same live per-channel levels. In the Retro hi-fi style each channel (or spectrum band) is an LED column instead. Ordinary audio files (MP3, FLAC, …), which have no per-channel meter, get twin needle meters in Retro hi-fi when there is room beside the transport keys — L and R, the music's level whatever the volume setting — either side of the transport keys; their red PEAK lamp lights when the music comes within half a dB of full scale. With reduced motion the needles show one still reading. The same group's Enable visualizations and Now-playing switches turn the meters, the signal path and the visualizer off on this device.

The pattern view — watch the module play

Track Info opens with the ⓘ button on the player bar, I or a click on the cover art (for the playing track), or Get info in a row's right-click menu; ◀ ▶ in its header (or ← / →) step through the list and Esc closes it. Open it on a tracker module and the panel leads with the module itself: channels, patterns, instruments — and a live pattern grid. Each pattern is laid out tracker-style — note · instrument · volume · effect — with the song's pattern order strip above it to jump anywhere. With Follow on, the playhead row tracks playback and the grid scrolls with the music, and every channel's column glows with its live level, in the same colour as its meter bar. Track Info shows only the fields a file actually has.

Modules that carry a song message — greets, release notes, ASCII art — show it exactly as written, spacing and all, and ▶ Scroller plays it as a demoscene scroller. A Made with row names the tracker software when the file records it, and BPM comes straight from the module's own tempo.

Which formats? The pattern grid covers the classic tracker family — MOD, S3M, XM, IT, MED, 669, MTM, OKT and the rest of the libopenmpt set. AHX and the Amiga exotica keep their per-voice meters and module details, HivelyTracker its module details, and SID and MIDI keep their own detail panels.

Multi-song files — the tune picker

A single SID, SNDH or SC68 file, an Amiga player-format module, or a console rip (NSF, NSFe, GBS, AY, SAP) often holds many separate tunes — a game's whole soundtrack in one file. Open Track Info on one and a tune picker lists every subsong: ▶ play (on the tune that's playing, pause and resume), + queue or ☰ add any one to a playlist, or Play all, Add all, ☰ Playlist and shuffle the whole set at once — and those single-tune picks live happily inside playlists alongside ordinary tracks. A file with more than 60 tunes lists the first 60, and Jump to reaches any tune by its number. In the desktop track lists and search preview, a file known to hold several tunes carries an N tunes badge. When a SID is part of the HVSC collection, each tune shows its real name and length from the Songlengths and STIL databases — so Tune 3 / 6 reads "Assembly" rather than a bare number — with the full STIL commentary below and the chip model shown as a 6581 / 8580 badge.

Track Info follows the style the equalizer, Stations, playlists and the queue share. In Retro hi-fi the panel is a component's spec plate: the cover sits in a bezel above a display strip (beside it in a narrow window) with the format, the length, the SID chip and — for a tracker, SID, MIDI, Amiga, Atari ST, PSF-family or multi-tune console tune — the renderer that plays it, then the audio details; the header's track line shows in a display window, and the tags are printed on a cassette insert. The tune picker becomes a keypad of numbered keys, each with its length when it is known (and its STIL name): the lamp of the tune that's playing is lit, amber while it's paused. Click a key — or move to it with Tab and press Enter — to play that tune, and the lit key pauses and resumes it; point at a key for its ▶, + and ☰ (on a touch screen they are always on the key). Both styles come in the light and the dark theme.

The song lengths and STIL come from gear → Renderers → HVSC SID database. Choose Download from the internet and SoniqBoom downloads them from the 6581.nl HVSC mirror (about 9 MB) and checks for a new HVSC release weekly — Check now checks at once, and the card shows the date of the song-length list in use and when it was last checked. Or choose Local DOCUMENTS folder and enter the HVSC DOCUMENTS folder on your computer. Either way your SID files are matched by checksum, wherever they are in your library. Offline mode downloads nothing.

While a download runs, the card shows its three steps — Download, Install and Apply to your SID tracks — with a progress bar: the percentage and megabytes of the file being downloaded (the song lengths, then the STIL commentary), or the megabytes so far when the mirror doesn't say the size, then how many of your SID tracks have been matched. The new song lengths and STIL are applied to your SID tracks straight away; there is nothing else to click. When it ends, the card says how: Done with the number of song lengths and STIL entries in use and of SID tracks they were applied to, Already up to date, that offline mode is on, or why the download failed (the mirror couldn't be reached, stopped sending data for a minute, refused or couldn't answer) with a Retry button — the database downloaded before stays in use meanwhile. If applying to your SID tracks fails, Apply to SID tracks tries again. The progress follows the server, so it is still there after you close Settings or reload the page; Check now and Re-extract SID metadata wait until it is over. Re-extract SID metadata shows its progress and result in the same place.

Playing the file itself starts at its default tune, marked default in the picker: the start song a SID or SNDH file names, and for Amiga player formats (played by UADE), console rips and SC68 disks the first tune that isn't empty (tracker modules start at tune 1); a tune you pick plays that tune. On the phone, Now Playing lists the playing file's tunes below the controls; tap one to play it, and its number follows the title. A tune that renders to silence shows “This tune plays only silence” instead of playing — in the web player, a very long C64 tune from its second play on.

Skip short tunes and broken tracks

Many SID, SNDH and console-rip files hold short sound-effect tunes next to the music, and collections hold short jingle modules. System → Settings → Skip short tunes (off by default; under 5, 10, 20 or 30 seconds) passes retro tunes that short by whenever a list or a tune list plays through — Play all, shuffle, the next track. Ordinary audio files (MP3, FLAC, …) are never skipped, and a tune you click still plays.

Only tunes with a known length count:

  • a SID tune — from the HVSC Songlengths database;
  • a tune of a multi-tune SNDH, NSFe or AY file — from the file itself;
  • the tune a file plays by default — from its length before any fade-out: for a module, YM, PSF or MIDI file once it is scanned, for an Amiga, AHX, SC68 or AdLib tune once it has played or SoniqBoom has measured it in the background while it was shown in a list (Playback preparation).

The setting shows how many tunes have a known length and, without any, links to the HVSC folder setting. In the tune picker a short tune is dimmed and tagged short, the header counts how many are skipped, Add all and the playlist button leave them out, and a file whose tune lengths are unknown says so.

With the setting on, Subsonic apps such as Feishin list a multi-tune file without its short tunes in an album or folder — its own entry too when its default tune is short, as long as another tune is listed. A file all of whose tunes are short, and a single short file, stay listed. Refresh the album in the app after a change.

A track that doesn't play right can be reported. In Track Info, Playback offers No problem, Glitched (plays, with wrong sounds) and Broken (doesn't play right), with an optional note; the same choice is on a row's right-click menu, on the phone's long-press menu (Report a problem…) and, when a track can't be played, on the message that says so (Mark broken, when the file itself failed to play). Reporting needs edit rights; every user sees the report — who made it, when, and which renderer and version played the track. Identical copies of a module, chiptune or SID file are marked too, and a file that is removed and comes back unchanged keeps its report; a changed file starts without one. A track marked broken, and one no engine can decode (corrupt — such as a YM4 file, or a .ym file that isn't a YM register dump), is passed by when a list plays through, while a click still plays it: if it then plays, SoniqBoom offers to clear the mark.

A track whose player refuses it the same way twice in a row — for example an Amiga module on which uade stops with score crashed — is marked can't play by SoniqBoom itself. The message that says so names the player and the reason (“title can't be played here — the Amiga player (uade) stops on this file: score crashed”), with no Mark broken offer; the track is passed by when a list plays through, and a click tries it once more. Track Info shows the reason, the player and its version, and when it was found, with no signal path and no Playback choice (unless a listener reported the track, so the report can be cleared). The mark is taken off when the player or SoniqBoom is updated, when the file changes, and when the track plays after all. A failure that isn't about the file — a timeout, a track you skipped while it was being prepared, a player that was stopped, a download cut short, a full disk — never marks a track, nor does a player that refuses one file after another (its marks are taken off until it plays a track again); a report a listener made stays on the track beside the mark.

One badge per row shows the most serious problem — red can't play / broken / corrupt / no tunes (passed by; no tunes is an archive of an online collection with no tune in it, shown where a copy of it is still on screen), amber glitched / partial (plays; a Sonix module whose instrument files are missing, which play as silence) — in track lists, search results, playlists, the queue, Track Info and on the phone. In the queue, rows that will be passed by are dimmed. Subsonic apps don't get tracks marked broken, tracks that can't be decoded or played or files whose default tune is short in random songs, similar songs (getSimilarSongs) or top songs; albums, folders, playlists, searches and the OpenSubsonic sonic-similarity lists still list them. The first time a track is passed by, a one-time message explains why. A Subsonic app that plays a track marked can't play gets an error naming the reason. To leave tracks marked can't play, corrupt or broken out of the lists altogether, set System → Settings → Tracks that can't be played to Hide them.

Equalizer & visualizer

A built-in 10-band equalizer (32 Hz–16 kHz, ±12 dB) shapes the sound band by band — toggle it with E or the EQ button. The panel names the track that is playing and draws the equalizer's curve over that track's live spectrum. In the Modern style the bright trace is the sound after the equalizer, the faint dotted trace the track as it comes in, and the glow under each band's knob follows that band's level.

  • Style — the Style switch at the top of the panel chooses the look of the whole app (see Style): Modern (the curve with a knob per band) or Retro hi-fi, a classic graphic equalizer. In Retro hi-fi each band is a slider in its slot, with an LED column beside it that shows the music's level in that band — green, amber, red, with a peak segment that falls back slowly. Above the sliders, a glowing Display strip shows the curve over the spectrum; the Display key turns it on or off. The presets are keys with lamps under the sliders: the lamp of the preset in use is lit, and Custom shows when the bands match none of them.
  • Adjust a band — drag its knob (in Retro hi-fi, its slider) up or down (0.5 dB steps; a readout shows the value and the band), or drag up or down anywhere in the band's column. Double-click a knob to set it to 0 dB; the mouse wheel over a knob moves it in 0.5 dB steps. With the keyboard, Tab to a knob, then ↑/↓ ±0.5 dB, Page Up/Page Down ±3 dB, Home/End −12 / +12 dB, Enter or Space 0 dB.
  • Presets — Flat, Bass Boost, Rock, Pop, Jazz, Classical and Vocal (in the Modern menu each with a small picture of its curve); the bands glide to the new setting. Reset sets every band to 0 dB and the pre-gain back to automatic.
  • Bypass (or B while the panel has focus) plays the track with every band flat, at the same level, so you can compare; press it again — or close the panel — to hear the equalizer again. Moving a band or picking a preset also ends the bypass.
  • Pre-gain and CLIP — when bands are boosted, the input is lowered by the curve's highest point (shown as Pre-gain), so the boost has headroom. The CLIP lamp lights when the output goes past full scale; Auto pre-gain then lowers the pre-gain by that much. The extra lowering stays until Reset.

The Volume leveling menu evens out loudness with the ReplayGain tags in your files — Per album (the default), Per track or Off. The moving spectrum follows the same settings as the other visuals: with reduce motion it stands still, and with Enable visualizations or Now-playing switched off only the curve is drawn (in Retro hi-fi the LED columns stay dark). A full-width visualizer plays behind the track list and cycles through its modes with V — oscilloscope, retro CRT scope, scrolling spectrogram, spectrum analyser, hyperspace tunnel, synthwave grid, wireframe globe, cosmic eye, lava lamp, and a singing raccoon; it starts with the mode you used last. In Retro hi-fi it cycles through the oscilloscope, the spectrum analyser and the CRT scope only; a mode only Modern has shows as the oscilloscope there. The spectrum analyser shows a bar per band — thirds of an octave from 25 Hz to 20 kHz, whole octaves in a narrow window, the octaves' frequencies printed underneath — with a peak mark that stays a moment above each bar and then falls. In the Retro hi-fi style the oscilloscope is an amber phosphor trace with a short afterglow over a printed grid, the analyser a faint cyan display of lit segments with amber peak segments and the CRT scope a faint amber trace — dim enough to read the list through. The visuals respect your system's reduce motion setting (the visualizer then shows one still picture), pause when the tab is hidden, and stay off while Enable visualizations or Now-playing is switched off. The player bar's record button (or N) shows the playing track's cover large over the list, with its title, artist and album; click it, press N again or Esc to close it; it also closes when you pick another view. In Retro hi-fi the cover is the label of a record turning on a turntable, under a display with the title, artist and album; it stands still while paused, with reduce motion, or with the Now-playing visualizations off.

No network pause between tracks. In the last 20 seconds of a track, the next one in the queue is fetched ahead of time, so playback moves straight into it without waiting on the network. With a Crossfade length set (gear → System → Settings, or gear → Preferences for accounts without admin rights), the current track instead fades out over its last that-many seconds while the next one starts and fades in (with repeat set to one, the track simply starts again). In the same place, Preload buffer waits until that many seconds are buffered before a track starts, and “Converting…” notice delay sets how long a conversion may take before its notice appears (retro and Amiga tracks show Rendering… after a second); these settings are saved in this browser.

Player bar. The seek bar shows the track's waveform once it is known. For a SID, tracker, Amiga, chip, AdLib, PSF or SNDH tune of known length it fills in from the left while the tune renders; other rendered tunes show it once they have rendered. Your keyboard's media keys, the lock screen and your system's media controls show the playing track and play, pause and skip, and while SoniqBoom is on screen the display stays awake as music plays. In the Retro hi-fi style the player bar looks like a cassette deck: the title and artist glow on a display window — for a tracker, SID or chip tune with an LED column per channel under them (beside them in a narrow window) — the times sit in small display windows, the waveform is an amber strip with a lit playhead, the transport and toolbar buttons are hardware keys (a lamp lights on a key that is switched on) and the volume is a ribbed fader. In either style, in a window 1100 px wide or less the radio, download, now-playing and cast buttons move into the toolbar's ⋯ menu, between 601 and 900 px the lyrics and playlists buttons too, and between 601 and 720 px the equalizer button.

Time-synced lyrics

Lyrics come from the file's own tags or, when it has none, from LRCLib or lyrics.ovh — the one that has been answering faster is asked first, the other only when it finds nothing; synced lyrics scroll line-by-line with playback. SID, tracker, chiptune, Amiga, Atari ST, PSF and AdLib tunes show only lyrics stored in the file — MIDI files are looked up online too. Open them with the Lyrics button in the player toolbar (a side panel — drag its edge to resize it, or focus the edge and press ← / →) or the Lyrics tab of Track Info. With Save fetched lyrics to files (gear → Metadata → Lyrics, off by default) lyrics opened in SoniqBoom's own player by an edit or admin account are written into a local file that has none; a lookup from a Subsonic app or a read-only account never writes to a file.

In the panel, click a synced line (or move to it with ↑ / ↓ and press Enter) to jump there in the track; scrolling the lyrics yourself pauses the follow for a few seconds. × closes the panel, and so does Esc while the keyboard focus is in it. In the Retro hi-fi style synced lyrics run on a display window like a teleprompter: the current line glows in the middle, the lines around it are dimmer, and SYNC / PAUSE lamps and a line counter sit along the top. Podcast & audiobook chapters

About the artist & tag editing

The Track Info panel also shows an About the artist card — a short bio and portrait, with a link to the full article — whenever the artist has one. The artist is matched through MusicBrainz using the album and track you're viewing, and the bio comes from the matched artist's Wikipedia page: "Ghost" on an Impera track is the Swedish band, not the apparition. A retro track — SID, tracker, Amiga, Atari ST or PSF-family — shows a Scene tab in place of Lyrics: the composer's Demozoo profile (real name, groups, aliases and links), the release the tune comes from and more by the same composer, plus the tune's Modland location and format. Its About the artist card then shows only a Wikipedia article: the one the composer's Demozoo profile links, or, when Demozoo doesn't identify the composer, the artist's Wikipedia page found as for other music. Below it, ✏️ Edit tags opens an inline form for title, artist, album, album artist, game, genre and year: Save tags writes the changes into the audio file itself (the game as a GAME tag) and updates the library at the same time. This works on local MP3, FLAC, M4A, Ogg, Opus, WavPack and Musepack files (in Docker, only once the music folder is mounted writable — remove :ro from its line in docker-compose.yml); every other track — network shares, archive members, modules and chip formats — gets ✏️ Edit info, which changes the library only and also covers composer, label and comment; when a Demozoo year or one you typed replaced the file's, ↺ Revert year to file brings it back. Saving either needs an edit or admin account. The Game row shows the game the music belongs to: a retro tune's game (usually the same name as its album, and an album you set is its game), with a note saying where it came from, or the GAME tag of a remix. When the file header, Modland, Demozoo, the song database, the archive name or the folder name call the game something else, those names follow on an also line (a name that is only the start of another one is not repeated) — game: finds the track by any of them. The folder name counts only while Album from folder name for retro formats is on, a Modland file-name guess only while Guess game from Modland file names is on, and the archive name only while Game from archive names is on.

Scene origins

Retro module files rarely carry proper tags — but the scene has spent decades cataloguing them. In gear → Metadata → Scene origin (Modland) SoniqBoom fingerprints each module and matches it against the Modland index, filling in the original author and adding a Scene origin row to Track Info that shows exactly where the tune sits in the archive — Modland: <format>/<author>/…. Refresh the index and apply it from the same panel.

Chip-music files that store their game's name (SPC, NSF/NSFe, GBS, VGM/VGZ, and PSF-family rips such as PSF, USF, GSF, 2SF or SSF) show it as the album and the game; other music files (MP3, FLAC, M4A, Ogg, Opus …) can carry a GAME tag. To read them again — the chip-music files whose game has not been read from the file yet, and every other music file's GAME tag — use gear → Metadata → Game names from file tags → Read game names (the other details read from those chip-music files, such as titles, are refreshed too); untick Include network shares to read only local files. From an FTP or SMB share, an MP3, FLAC or M4A file is read only as far as its tags where the file allows it (files inside archives are read whole), and Cancel stops the run after the current file. A Modland match also fills an empty album with the game the tune belongs to. With Guess game from Modland file names (on by default), Amiga and tracker modules with an exact Modland match can take the game from the Modland file name such as gold of the aztecs-intro when the track's title matches the part after the dash and either other files in the same Modland folder share the game prefix, or the part starts with a usual tune-part word such as intro, title, ingame, level or gameover (an Amiga custom-format tune, whose title is its file name, needs other files in the same Modland folder to share the game prefix). Such a game is spelled as the game title lists spell it when they know it on the track's platform — backtothefuture3-intro gives “Back to the Future III”, chuckrock 2 “Chuck Rock II” — and as the file name has it otherwise; these guessed albums carry a small “guessed from Modland file name” note in Track Info. An album you typed is never replaced. An album from the file itself is kept too, except that an exact Modland match completes an SPC game name that the file's tag cut off at 32 characters. Turning the option off removes only the albums it guessed.

In gear → Metadata → Song database (audacious-uade-tools), Download fetches the song database of the audacious-uade player (about 27 MB) from GitHub, always at the same reviewed commit (Validated set opens it on GitHub), and Apply to library matches your modules against it by checksum. If that commit is no longer available, the latest files are used and the status line marks them as not validated; the status line also notes when newer data exists upstream. An exact match fills what is still empty: the artist, the label (the publisher or group), the album (the game or production — it also replaces an album guessed from a folder or a Modland file name), the year and — for many Amiga modules not played yet — the length. A production name that several groups used carries the group, e.g. “Megademo (The Silents)”. While Re-apply automatically after each library scan is on (the default), a download and every scan apply it too. Reset enrichment removes the artists, labels, albums and years it filled and turns the automatic re-apply off; lengths stay. Tags in your files and anything you typed are never replaced, and a year from the database is marked in Track Info. The database is audacious-uade-tools by Matti Tiainen, compiled from about 400 scene sources and licensed CC BY-NC-SA 4.0.

Where a game's name comes from

A game you typed, or an album you set on a retro track, is always its game. Otherwise a retro track's game is the first name these sources give it, in this order:

  1. The file itself — the game in an SPC, NSF/NSFe, GBS, VGM/VGZ or PSF-family header, or a GAME tag.
  2. Modland — the game folder of the tune's exact Modland match.
  3. Demozoo — the game Demozoo lists the tune as the soundtrack of, when the tune's composer and title match and the tune is named after that game (“Rick Dangerous”, “High Technique (tune 3)”); from the Demozoo index under gear → Metadata (if its status line there says refresh the index to add game names, use Download / refresh index).
  4. The song database (audacious-uade-tools) — the game of an exact checksum match.
  5. A Modland file name such as gold of the aztecs-intro, while Guess game from Modland file names is on — spelled as the game title lists spell it when they know it.
  6. The archive's name, when it is the name of a known game of the track's platform, while Game from archive names is on.
  7. The folder or archive name, while Album from folder name for retro formats is on.

The names the other sources give are the game's other names: Track Info lists them on the also line, and game: finds the track by any of them.

Game names from archive names

A retro track inside an archive takes the archive's name as its game when that name is a known game of the track's platform — Turrican.lha for Amiga TFMX tunes, Super_Mario_World.zip for SNES SPC rips. The name is compared with the game titles of the platform only: a SID with C64 games, an Amiga module with Amiga games, a YM or SNDH tune or an Atari ST player's tune with Atari ST games, an AdLib or Sierra AGI tune with DOS games, an SPC with SNES games, a PSF with PlayStation games, and so on; case, accents, punctuation, a leading “The”, Roman numerals, dots between letters and region tags such as “(Europe)” are ignored, a name written without the spaces a title has matches it (Megaman2.zip is “Mega Man 2”), and the game is shown as the title list spells it. Skipped are generic names (music, intro, disk 1 …), names of a part of a game's music, pure numbers, any name the archive's own tunes credit as their composer, artist, group, label or releaser, and an archive that holds a single tracker module or SID named like it (such as axelf.mod.zip); the next archive out is looked at instead. A one-word name shorter than eight letters needs two title lists of the track's platform to agree, and a tracker module (MOD, XM, S3M, IT, MED, AHX …) needs a name of two or more words that two lists of its platform agree on and that is not the title of a module in that archive.

The option is in gear → Metadata → Game names from archive names (on by default); it applies right away and after each scan, Track Info notes such a game as “from the archive name”, and turning it off removes only the names it added. The game titles of Wikidata (CC0), No-Intro, the MAME software lists (CC0) and ZXDB (ODbL) are included, and the C64 tunes in the GAMES folder of your own HVSC copy count as C64 games. Download TOSEC (home computers such as the C64, Amiga, Atari ST, ZX Spectrum, Amstrad CPC and MSX, about 100 MB) and Download Redump (disc consoles such as the PlayStation, Saturn and Dreamcast, about 10 MB) add their titles; each is fetched only when you click it, shows its progress, can be stopped with Stop and can be removed again. The downloaded files are kept in SoniqBoom's data folder: after Remove, Add … from the downloaded pack (or lists) puts the list back without downloading; Update downloads the TOSEC pack only when tosecdev.org has a newer release (and uses the kept pack when the site can't be reached), and says so when nothing changed; a Redump download that was stopped — or interrupted by stopping SoniqBoom — is continued with Continue the Redump download, which fetches only the systems still missing, while a stopped TOSEC download starts again; a Redump system that can't be reached keeps the titles of its kept list, and the next Update that reaches every system clears the note about it. A kept file that turns out to be damaged is removed (the next download fetches it again); one that can't be read for another reason — a disk error, a missing permission — is kept. Delete the downloaded pack (or lists) frees the space; the title list stays. Wikidata data is used under CC0; ZXDB contains information from ZXDB, made available under the ODbL.

High-resolution PCM — 24-bit FLAC, WAV and the like — streams to the browser without re-encoding.

10Casting Beta

Send what you're playing to a TV, speaker or receiver on your network.

Casting is in Beta. Chromecast, AirPlay and DLNA targets are supported; behaviour can vary by device. Each target type needs its Python package in SoniqBoom's environment — pychromecast, pyatv or async-upnp-client (not included in the Docker image).
  1. Press the cast button in the player toolbar.
  2. Pick a device from the list — discovered Chromecast, Apple TV / HomePod (AirPlay), and DLNA receivers appear together.
  3. Playback moves to that device. SID, MIDI, tracker modules, AHX, HivelyTracker and console chiptunes (NSF, SPC, VGM …) are rendered to standard audio first, so they cast like any FLAC. AdLib, Atari ST, PSF-family and other Amiga player formats are not rendered for casting.
  4. Some AirPlay devices show a PIN the first time you connect — type it into the pairing dialog to authorise SoniqBoom. The pairing is remembered, so the PIN isn't asked for again.
  5. Open Audio quality in the picker to choose: Auto (the file as it is when the device plays it, otherwise lossless when the device supports it, otherwise MP3 320) or MP3 320 (smallest bandwidth, widest compatibility). The picker also lists Original and FLAC; these choose the format the same way as Auto. The picker on the phone page offers Auto and MP3 320.
SoniqBoom as a DLNA server Beta — off by default. Besides sending audio out, SoniqBoom can announce itself as a DLNA Media Server so UPnP controllers on your network (some smart TVs and receivers) can browse and play your library. Turn it on in gear → System → Services; while it is on, any controller on the same network can browse your library under Music → All Tracks, Albums, Artists (album artists, then their albums), Genres, Folders (your library folders, then their subfolders and tracks) and Playlists (the playlists their owners share with every account), with covers where a track has one, search it, and play any track without signing in. SID, MIDI, tracker modules, AdLib, Atari ST, PSF, console chiptunes and the Amiga formats are offered as FLAC and as MP3 (in that order) and start at once; the first time a tune plays in FLAC or in MP3, the player can't skip ahead within it. Controllers find it through SSDP on UDP port 1900, so a firewall on the server must let that port through.

11Multi-room sync

Play the same music in step across the devices on your network — one device leads, the rest follow in lockstep.

SoniqBoom has a dedicated multi-room controller. Open it at /multiroom on your server — for example http://localhost:8080/multiroom, or your server's own address. One device becomes the master and drives playback; every other device joins as a listener and stays in sync.

Start a room — the master

  1. Open /multiroom in a browser on the device that will lead.
  2. Type a device label (for example Kitchen speaker).
  3. Click + Create new room, give the room a name, then Create & become master.
  4. As master you browse Tracks, Playlists and Albums, search, and control playback — play/pause, next/previous, shuffle and repeat; Up next shows the room's queue. The queue passes by the same tracks the main player does — offline, reported broken or undecodable, and short tunes while Skip short tunes is on. The Listeners panel shows every device that has joined, marked Master or Follower.

Join a room — a listener

  1. Open /multiroom on another device and type a device label.
  2. Pick the room under Active rooms — you join as a listener and follow the master in sync, with a live sync-drift meter on screen.
  3. Press ← Leave to drop out. When the master leaves, listeners see Master left the room with a Become master button; a device that opens a room with no master becomes its master.

Stream a station to a room

A room isn't only for your own library. Open the master's 📻 Radio tab, pick any of your favourite internet-radio stations, and it plays to every device in the room at once. Add a network share — FTP, SMB, WebDAV or a web folder

In the admin panel's Music Folders section, switch from Local Path to the Network Share tab and pick a protocol:

Tracks on a share start playing while they download: an MP3, WAV, Ogg or Opus file, or a FLAC with a seek table, plays from its first bytes, and a seek far ahead of what has arrived can be read straight from the share. The Scan ZIPs box on the Local Path row is the same switch as Scan ZIPs in System → Settings.

With an FTP share connected, the Library tab adds FTP Connection Pools: for each FTP server, set how many connections scans (Scan workers) and playback (Stream workers) may use, and Save. Online collections

The admin panel's Collections tab adds public music archives to your library without copying them: each one is listed from the archive's own index (scene.org from its folders), as a folder of its own in the folder tree, browsable and searchable at once, and a tune is downloaded only when you play it (or open its Track Info). Every collection is off until you switch it on.

Aminet and scene.org keep most of their music in archives (LHA or ZIP) — one module, or a whole music disk. Such an archive is listed as one entry, its format shown as LHA package or ZIP package. When you play it or open its Track Info, the archive is downloaded (a large ZIP only in part) and the tunes inside it take its place in the folder: the first one keeps the entry's place in your queue and playlists, and the others follow it in the queue. Tunes on an Amiga or C64 disk image inside the archive are listed too. An archive that holds nothing SoniqBoom plays leaves the library as soon as that is known: playing it (or opening its Track Info) says what it holds instead — an Amiga or PC program, a disk image or archive in a format SoniqBoom doesn't open — and its playlist entries are kept. An archive that can't be opened is marked corrupt.

A tune of an online collection that is also a file in your folders or shares — the same file, known by its checksum (from Modland's checksum list, the HVSC song database, or the tune's own download once it has played) — is one tune with two copies: your copy is the one shown first in Duplicates and the one kept when duplicate copies are hidden, and playing the collection's entry plays your copy, with nothing downloaded.

Modland

Switch on Modland catalogue and SoniqBoom downloads the index of Modland's module archive (about 6 MB) and lists the tunes it can play — about 330,000 tunes of Amiga, C64, Atari ST, console and tracker music — under a Modland folder in the folder tree. Switched on again later, it updates a recent index it kept instead of downloading it again. The status line shows the progress while it is built and then the number of tunes, the date of the index and when it was last refreshed.

  • The folders follow Modland's own layout: format, composer, and for console rips the game. Each tune shows its title (the file name), its composer, its format, the game it belongs to where Modland's folders or file name say so, and its retro genres — browsable, searchable and playable right away. Its length shows once it has been played.
  • Nothing is copied ahead of time: a tune is downloaded from Modland when you play it or open its Track Info (for tracker, SID, Amiga, Atari ST, PSF-family and multi-tune console chiptune files), together with the files its format needs beside it (a TFMX tune's sample file, a PSF rip's library files), and plays from SoniqBoom's remote cache while it is kept there (its size is Remote cache (MB) under System → Settings). That first download reads the file itself — its length, number of tunes, its own title and tags, including the composer the file names (Modland's credit names one where the file doesn't); an open page shows them at once. With Modland's checksum list installed (gear → Metadata → Scene origin (Modland)), Amiga modules show how many tunes they hold before that when the song database is installed too, and HVSC SIDs when your HVSC copy is set up. The player also prepares the one track that plays next, and a Chromecast (casting is in Beta) loads the next tune of its queue shortly before it starts. Folder views, searches, artwork, waveforms, VU meters and background passes never download a catalogue tune on their own (except with For tunes shown in lists, below). At most 120 new tunes are downloaded within ten minutes; a play beyond that says to try again shortly.
  • Tunes: Everything except the large PC tracker folders (the default) leaves out Fasttracker 2, Impulsetracker, Screamtracker 3, Fasttracker and Multitracker; Everything lists about 415,000 tunes.
  • Show catalogue tunes to Subsonic apps is off by default: Subsonic apps and the DLNA Media Server Beta then see your library without the catalogue, and a catalogue tune answers “not found” to them. Switched on, an app that syncs or caches a whole library for offline use tries to download the whole catalogue from Modland.
  • Read details of tunes not played yet: When I open Track Info (the default) downloads a tune's file when you open its Track Info. For tunes shown in lists also downloads, one at a time, the SC68, SNDH and console chiptune files (NSF, NSFe, GBS, HES, KSS, AY, SAP) shown in a list that haven't been read yet, so their length and tags show as you browse — and, for SC68, SNDH, NSF, NSFe, GBS, AY and SAP files, their number of tunes. These downloads have their own limit, which always leaves room for plays. Amiga modules and HVSC SIDs show their number of tunes either way when Modland's checksum list is installed (with the song database for Amiga modules, and your HVSC copy for SIDs).
  • The index is refreshed on the schedule picked in the menu right of Refresh now — Daily (the default), Weekly, Every 2 weeks or Monthly, counted from the last successful refresh — or at once with Refresh now; the status line shows when the next refresh is due. Tunes Modland added appear, removed ones go, a tune Modland moved or renamed keeps its ratings, play counts, favourites, history and playlist entries, and a changed file is downloaded again on its next play.
  • A refresh downloads only the changes since the last one — Modland's daily changelogs, usually a few kilobytes in all. The full index (about 6 MB) is downloaded only when needed: the first time the catalogue is switched on, after a large reorganisation at Modland, when the changelogs can't be read or don't add up to Modland's own file count, after about six weeks without an update, and about once a month as a check. The status line says what the last update downloaded (“updated from 3 changelogs (2.1 KB)”, or “full index (5.5 MB: …)” with the reason), up to which day the index holds Modland's changes, and how much the index updates have downloaded in all.
  • A failed or incomplete download keeps the catalogue as it was and is tried again an hour later (an index that doesn't look like Modland's, a day later), whatever the schedule; a new index that lists far fewer files than the current one is taken only when you press Refresh now after the status line reports it.
  • When Modland can't be reached, tunes played before still play from the cache; the others report that Modland can't be reached right now and count as unavailable under Tracks on unavailable drives (see Library display under Settings & integrations) — marked offline by default, or left out of searches and lists with Hide them. The Modland folder shows offline for a while and stays browsable; the next play after that tries Modland again.
  • Switching the catalogue off removes its tunes and the Modland folder. Ratings, play counts, favourites, playlist entries and what the plays read (lengths, tags) are kept and come back when you switch it on again; a playlist edited meanwhile keeps its catalogue entries. The same holds for the tunes a narrower Tunes selection leaves out.
  • In Recently Added and Unplayed, and in Subsonic apps' lists of newest albums, the tunes of the first build — and those a wider Tunes selection adds later — sort as the oldest; tunes added by a later refresh show the day that refresh added them.
  • The catalogue needs about 1 GB of server memory (about 1.2 GB with Everything).
SoniqBoom connects to Modland to update the index on the schedule you pick (or when you press Refresh now) and to download the tunes that are played or about to play, over at most three connections at a time. Thanks to Modland and its maintainers.

Keep your library fresh

Local folders are watched automatically — files you add, change or remove are picked up a few seconds after the changes settle, and a file that is still being copied or downloaded is picked up once it is complete. Changes made while SoniqBoom was stopped are picked up by a rescan of the local folders a few minutes after it starts (Rescan local folders after startup in Settings). A local folder that can't be watched (for example on Linux when the system's limit on watched folders, fs.inotify.max_user_watches, is reached) shows Not watched in the Library tab's folder list, with the reason below it: it is rescanned every 15 minutes, and watching it is tried again automatically. A folder that is watched except for some of its subfolders (the limit was reached while a folder was moved or copied into it) shows Partly watched: it is rescanned every 15 minutes too, and the missing subfolders are added automatically once the limit allows. Network shares are re-checked on a background poll that adapts to each share — every 5 minutes for one that changes often, up to every 4 hours for a stable one. A check finds files added, removed or renamed in any folder of the share (in a share with many levels of folders, within a few checks); a file rewritten under the same name in a large share can wait for the next full check (every fifth check, and any check more than 3 hours after the last full one). The Library tab's Auto-Refresh (Remote Shares) section lists each share with when it was last checked and when it will be checked next; its Check now button checks at once, and a notice appears only when new tracks are found. To rebuild everything by hand, use ↻ Rebuild Index; to re-scan a single folder, use its Re-Index button. While a scan is running you can Pause it and later Resume from where it left off — handy for easing server load during busy listening.

The Library tab's Library Health cards show how many tracks and scan folders are indexed and whether the search index is in order. If titles, artists or albums show the replacement character �, or modules show a placeholder title such as <unnamed>, Repair Garbled Metadata reads them again from the files (a placeholder title becomes the file name): Scan for Garbled Titles counts them, Repair Now fixes them (Only tracker / chiptune files keeps it quick).

Back up & restore

The admin panel's Backup tab exports your whole database to a single date-stamped file (soniqboom-YYYY-MM-DD.sbz) — a compressed snapshot of your track index and metadata, waveforms, star ratings, every account's play counts, listening history, playlists and radio Favorites, your scan-folder list and library settings. On restore, each account's data goes to the account with the same user name; data of a user name with no account on the server is kept aside and joins the account an admin later creates with that name (never one a visitor signs up for). ↑ Import .sbz restores such a file into the running server: it replaces the library index, and changes made since the export are lost. When it is done, the tab shows Import complete with the number of tracks restored. On the server (from inside the SoniqBoom folder), .venv/bin/soniqboom export backup.sbz writes the same file. To restore one, stop SoniqBoom, run .venv/bin/soniqboom import backup.sbz, and start SoniqBoom again (the import refuses to run while the server is using the data folder). The import replaces the library index; changes made since the export are lost. In Docker, from the folder with docker-compose.yml and the .sbz copied there (for the HTTPS setup, add the same -p and -f you use for that setup — e.g. -p soniqboom -f deploy/docker-compose.https.yml — to every command):

docker compose stop
docker compose run --rm -v "${PWD}:/backup:ro" soniqboom soniqboom import /backup/soniqboom-2026-10-01.sbz
docker compose start

With the server stopped, docker compose run --rm -v "${PWD}:/backup" soniqboom soniqboom export /backup/soniqboom.sbz writes a backup the same way. In Docker, back up the whole soniqboom-data volume (/data) as well; the caches in /data/cache/remote, /data/zip-extracts and /data/soniqboom/cache can be skipped. The same tab shows the Last known-good snapshot — an automatic copy of the library index (library.json.prev in the data folder), refreshed each time the server starts and the index loads cleanly. If the live index is ever damaged, stop SoniqBoom, copy library.json.prev over library.json in the data folder, and start it again. Recent changes are kept in library.aof beside it until they are folded into the index, and are applied at the next start; if that file may be damaged too, delete it as well — those changes are then lost.

The library database carries a version number (Database V2 in gear → System → About). When a new SoniqBoom release finds a database of an older version, it first copies the files into backups/db-v1-<date-time>/ in the data folder — with a README.txt explaining how to go back — and only then converts them; a backup that can't be made (too little disk space, for example) stops the start with a message, and nothing is converted. Those copies are kept until you delete them. A database written by a newer release than the one starting is refused rather than opened.

The backup holds your library database, not the audio files or SoniqBoom's settings. User accounts, saved play queues, and the favourites, album / artist ratings and bookmarks from Subsonic apps are kept in SoniqBoom's data folder (users.json, subsonic_state.json and secret.key), not in the .sbz — back up that whole folder too, keeping those files together, along with your music. It is ~/Library/Application Support/SoniqBoom on macOS, ~/.local/share/soniqboom on Linux (or $XDG_DATA_HOME/soniqboom), /data in Docker, or the data_dir / SONIQBOOM_DATA_DIR you set. Back up SoniqBoom.conf and prefs.json as well — your network shares, folder aliases, services and other admin settings. They stay in the macOS / Linux folder above even when you set a different data folder (SoniqBoom.conf is wherever SONIQBOOM_CONF points, if you set it); in Docker they are in /data/soniqboom on the volume. On a native install, share passwords and scrobble tokens only work on the machine that saved them: after moving to another machine, enter them again. In Docker they are encrypted with the key in /data/credential.key; keep that file with the rest of /data.

System notes

RAM & disk. SoniqBoom keeps your entire library index in memory, so browsing and search stay instant even at six-figure track counts — plan for RAM that grows with the size of your collection; the optional Modland catalogue needs about 1 GB more. The initial scan runs at roughly two minutes per 50,000 tracks. On disk, SoniqBoom keeps a snapshot of the library plus a render / transcode cache for instant replay — adjustable from 256 MB to 100 GB in gear → Renderers, where Cache size (MB) shows the current limit.
CPU. SoniqBoom sizes its work to the CPUs it may use (a container's CPU limit counts): a scan reads files in about half that many worker processes (2 to 16), and up to about half that many retro tunes render at once (at least 2). To choose the numbers yourself, set SONIQBOOM_SCAN_WORKERS and SONIQBOOM_RENDER_SLOTS to whole numbers in the server's environment — for example SONIQBOOM_SCAN_WORKERS=4 bash run.sh, or the environment list in Docker.

Scrobbling

Subsonic apps

Copy your server URL from gear → System → Subsonic / OpenSubsonic API and sign in with your SoniqBoom username and password. Apps that sign in with a token (salt + hash) work with your SoniqBoom password too. You can optionally give them a separate Subsonic app password: click Generate new password under gear → System → My Account (or gear → Preferences for accounts without admin rights) and copy it into the app — it is shown once, and from then on token apps must use it. In Subsonic apps, tracks that have no album are listed as albums named after their folder (Group album-less tracks into folder albums in the Subsonic panel, on by default); a folder shared by many artists, such as a compo pack, becomes one album per artist, and letter folders (A, B … or A-F) are grouped per artist under their parent folder and named after it, so an artist gets one album for the whole archive rather than one per letter. Turn the option off to reach those tracks only by browsing folders. Then see Listen anywhere.

🧩

What Subsonic apps see

Apps list one music folder for each scan folder in your library. A file that holds several tunes (SID, NSF and similar) also lists its other tunes in album and folder views as “Title (Tune n/N)” — up to 60 per file; each of those entries plays that tune. Downloading the original file from an app needs an admin or edit account. An app can ask for MP3, Ogg or FLAC (and WAV for files SoniqBoom converts anyway), and for a maximum bit rate, which is met by encoding to MP3 or Ogg. Apps' internet-radio list is the signed-in account's radio Favorites, played through SoniqBoom; any account can add, change and remove stations of its own list from the app. Apps also see the artist of a SID, tracker, Amiga, Atari ST or AdLib tune as its composer, and an album's label as its record label. An app's artist page gets the biography and photo Track Info finds for that artist and, for a scene musician, the library's artists who share a scene group with them as similar artists. An admin can add, change and remove accounts from an app: its admin role makes an Admin, any role that changes content (download, playlist, jukebox …) an Edit account, and none a Read-only one; changing accounts or passwords from an app needs the main password (u with p, or HTTP Basic), not a token or API key. For app developers: SoniqBoom reports Subsonic API 1.16.1 with the OpenSubsonic extensions songLyrics, formPost, indexBasedQueue, apiKeyAuthentication, topSongsByArtistId, transcoding, transcodeOffset, playbackReport and sonicSimilarity — apps can report what is playing with reportPlayback and find similar tracks with sonicSimilarity; f=jsonp requests must send their own credentials (u with p or with t and s, an API key, or HTTP Basic) and never use the browser session; a request with no credentials gets Subsonic error 10.

Optional services

Changes take effect after a server restart — use Restart now in the panel. While a service is off, its pages and API answer “not found”. On the server (from inside the SoniqBoom folder) you can do the same with .venv/bin/soniqboom services list and … services enable / disable followed by subsonic, multiroom, cast or dlna_server (in Docker: docker compose exec soniqboom soniqboom services list), then restart.

Game names from archive names

Download TOSEC and Download Redump add more titles on request. It applies right away and after each scan; turning it off removes only the names it added.

Retro genres

A retro track whose file names no genre is listed under the genres SoniqBoom knows for it: what it is — Game, Demo, Cracktro, Music Disk, Diskmag or Scene — and its platform — SID, Amiga, Atari ST, NES, SNES, Game Boy, Mega Drive, PlayStation, ZX Spectrum, AdLib, MIDI and more. They come from the track's game (from any of its game sources), console-rip formats, Demozoo (the demo, cracktro, music disk, diskmag or game released the same year that uses the tune, and the party competition it entered — to add these, use Download / refresh index and then Apply to library in gear → Metadata → Scene groups (Demozoo)), its composer's Demozoo group, HVSC's GAMES and DEMOS folders and folder names such as games, demos, intros, cracktros, musicdisks or parties inside a music folder. In gear → Metadata → Retro genres, Game and group names as genres (on by default) also adds the game, the composer's scene groups and the party, so a Subsonic app can browse a game's or a group's tunes by genre; a large library then lists many more genres. A genre in the file's own tags (other than the format words SoniqBoom adds, such as Chiptune or C64), or one you type in Track Info, replaces them. Track Info, the Genres view, genre search (genre:Cracktro) and Subsonic apps list them: an app shows the first one as the song's genre and all of them where it shows several.

Library display

Under System → Settings you can hide duplicate copies (in search and/or folder views), turn Use folder art on or off and choose which filenames count as folder art, and toggle ZIP-archive scanning — Scan ZIPs for local folders and Scan ZIPs on remote shares for archives on FTP, SMB and WebDAV shares.

Tracks on unavailable drives decides what happens to tracks that can't play right now: tracks on a drive or share that isn't connected (on a share, unless their file is in SoniqBoom's cache) and Modland catalogue tunes that aren't cached while Modland can't be reached. Mark them (the default) lists them dimmed with an “offline” badge (its tooltip says whether the drive, the share or the catalogue is offline); Hide them leaves them out of searches, track lists, smart views and their counts, while playlists, the queue, the Duplicates view and any folder you can still open list them, marked; Show them as usual lists them unmarked. With Mark or Hide, shuffle, Instant Mix, More like this and the next track skip them; a track you click still tries to play and says why it can't. While Hide duplicates in search is on, Mark and Hide list a duplicate whose best copy can't play by the best copy that can, until that drive or share is back. The lists update by themselves when a drive or share goes away or comes back (a local drive is checked every 30 seconds while the web app is in use; one that stops answering counts as gone at the next check, within about a minute; a drive whose folder is still there but empty counts as not connected while the library has tracks in it). The setting applies to every user of the web app and the phone page; Subsonic apps and the DLNA Media Server Beta list these tracks as usual. On the phone it is under Settings → Library, where admins can change it.

Tracks that can't be played decides what happens to tracks marked can't play (refused the same way twice by their player), corrupt (no engine can decode them) or broken (reported by a listener) — see Playing music. Tracks marked glitched or partial still play, and this setting never hides them. Mark them (the default) lists them with their badge; Hide them leaves them out of searches, track lists, smart views and their counts, while playlists, the queue, the Duplicates view and any folder you open list them, marked; from there a track can still be played or its mark cleared. Either way shuffle, Instant Mix, More like this and the next track skip them, and a track you click still tries to play. While Hide duplicates in search is on, Hide lists a duplicate whose best copy can't be played by the best copy that can — or, when no copy can play right now, by a copy that is listed (one on a drive that isn't connected, marked offline). Open pages update by themselves when the setting changes or a track is marked or its mark is cleared. Both settings can hide at once: a track is left out when either one hides it. The setting applies to every user of the web app and the phone page; Subsonic apps and the DLNA Media Server Beta list these tracks as usual. On the phone it is under Settings → Library, where admins can change it.

15Troubleshooting

The handful of things people ask about first.

A track is listed but won't play

The message says why. Usually its renderer isn't installed (or, after a system upgrade, no longer runs): re-run bash install.sh (it installs them all), or install the one package SoniqBoom names in the error — sidplayfp, fluidsynth, libopenmpt, uade, libgme, adplay, psgplay, sc68, zxtune123 or kssrender. The HivelyTracker (.hvl) and StSound (Atari ST .ym) engines are built the first time such a tune plays; outside Docker that needs a C compiler (HivelyTracker) and a C++ compiler (StSound). A tune that needs a file beside it — an AdLib instrument bank, a PSF rip's library file — names the missing file; a damaged file, or a tune that renders nothing but silence, says so. gear → Renderers → Renderer Status shows what is installed. Everything else keeps working in the meantime.

A track shows an “offline” badge

Its drive or share isn't connected right now — or, for a Modland catalogue tune, Modland can't be reached — and it can't play from SoniqBoom's cache. Reconnect the drive, or wait for the share or Modland to come back: nothing was removed from the library, and the badge goes once SoniqBoom reaches it again. Meanwhile the folder tree marks the drive or share unavailable (the Modland folder shows offline). A drive folder that is still there but empty counts as not connected while the library has tracks in it. To leave such tracks out of searches and lists instead, choose Hide them under System → Settings → Tracks on unavailable drives.

A SID tune shows the wrong length

Configure HVSC in Settings — without it, a SID plays for the SID duration (System → Settings, 3 minutes by default) that was set when the SID was scanned; changing the setting later doesn't change SIDs already in the library.

MIDI sounds thin or silent

Install or select a SoundFont in Settings; MIDI is synthesised from the active .sf2 or .sf3 bank, and without one a MIDI file reports No soundfont available. When the chosen SoundFont is on a drive that isn't connected (or was moved), a MIDI file doesn't play with another one: it says The chosen SoundFont “…” can't be found, and gear → Renderers → Soundfonts says so above the list — reconnect the drive, or choose another SoundFont there.

I'm locked out / forgot the admin password

After 15 failed sign-ins within 15 minutes, an account is locked for 15 minutes and the sign-in page says Too many failed attempts — wait, then try again. To reset a forgotten password, run this on the server host (inside the SoniqBoom folder): bash setup-admin.sh -user <name> -passwd '<new password>' (add -role admin to restore admin rights) — it takes effect immediately and signs that account out of the web app everywhere. See Manage your library & users.

If the sign-in page says the user accounts file could not be read, no account could be loaded from users.json in the data folder or its copy users.json.bak: both are damaged or missing, or users.json can't be read at all (for example a permission error — the copy isn't used then). A damaged file is moved aside as users.json.corrupt-<time> or users.json.bak.corrupt-<time>. Nobody can sign in or use the server — the DLNA Media Server Beta doesn't list or play anything either — until you put a good users.json back (from a backup of the data folder, readable by the user SoniqBoom runs as; the running server picks it up within a few seconds) and click re-check, or create an admin account with the command above (-role admin). Creating an account starts a new account list: the accounts in the unreadable file are not brought back.

A scan reports files it didn't index

A file whose metadata can't be read within about 90 seconds, or whose reading crashes the scanner's worker process, is skipped and counted as a scan error, and the scan goes on with the next one. When five files inside the same archive time out in a row, the rest of that archive is skipped too. The automatic rescans (the folder watcher and the rescan after startup) try a skipped file again only after a wait that grows each time it is skipped — an hour, then four, then sixteen, up to a week; a file that has changed is tried at the next scan; each scan tries a limited number of them. If a network share stops answering during a scan, the scan shows Waiting for … to answer and waits up to about three minutes; if the share is still silent, the rest of that library folder is left for the next scan. Tracks already in your library stay. Once the files or the share are readable again, use the folder's Re-Index button — it tries skipped files again without the wait.

A network share won't connect

In the admin panel's Music Folders → Network Share form, use Test before connecting — it reports the exact connection error. Check the host, share name / path and credentials, and that the server can reach the share on your network. The form connects to SMB shares on port 445 and to FTP servers on port 21; a WebDAV URL can name its own port.

A cast device doesn't appear

It must be on the same Wi-Fi / LAN as the server, and casting is in Beta — behaviour varies by device. Wake the device, then use the picker's Search again button. In Docker, finding devices and the DLNA Media Server Beta need the container on the host's network (network_mode: host — remove the ports: lines; the server is then on the host's port 8080), and casting needs the cast packages (pychromecast, pyatv, async-upnp-client) installed in the image.

Settings or shares are gone after a Docker update

In Docker, SoniqBoom.conf (shares, folder aliases, services and other admin settings), prefs.json, SoundFonts you add, and saved share passwords and last.fm / ListenBrainz logins are kept on the /data volume. A container from an image before 1.14.0 kept its settings, and the SoundFonts added in it, inside the container, so after the first update to 1.14.0 or later, settings (shares, services, sign-up and password rules, renderer settings, the Re-apply automatically switches) need to be set once more — Allow self-registration is back on until you switch it off again. Enter them in the admin panel; from then on they're kept. Add the SoundFonts again under gear → Renderers → Soundfonts (copied out of the old container with docker cp soniqboom:/app/soundfonts ./old-soundfonts before it was replaced, or downloaded again), and enter the last.fm / ListenBrainz logins again under gear → System → My Account (admin accounts only).

The app didn't change after an upgrade

SoniqBoom is an installable PWA, so the browser may still be serving a cached shell — reload the page (or remove and re-add the installed app) to fetch the new version.
